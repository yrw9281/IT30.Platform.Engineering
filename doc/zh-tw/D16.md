# Day 16 - 自動化建置與推送：Docker Image 封裝與 Tag 版本管理策略

## 前言

部署時最重要的是「到底跑了哪一份程式」。Image tag 若可覆寫就不夠可靠，因此 CI 應輸出 Git SHA、版本與 digest 等可追溯資訊。

## 建置 metadata 的規劃片段

```yaml
- name: Build and push
  uses: docker/build-push-action@v6
  with:
    push: true
    tags: |
      registry.example.internal/catalog-api:${{ github.sha }}
      registry.example.internal/catalog-api:1.2.0
```

## Tag 與 digest 的用途

```text
human-friendly tag: 1.2.0
commit traceability: 4f92e8a
deployment identity: registry.example.internal/catalog-api@sha256:******
```

release tag 適合人類閱讀；Git SHA 適合追蹤來源；digest 才是部署時不可變的內容識別。正式環境的 GitOps 宣告應優先引用 digest。

## 結語
