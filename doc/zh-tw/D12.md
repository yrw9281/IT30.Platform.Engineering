# Day 12 - 遙測資料轉運站：部署與配置 OpenTelemetry Collector

## 前言

Collector pipeline 把接收、處理與輸出拆成可獨立組合的元件。集中治理能避免把脫敏與後端端點散落在所有應用程式內。

## 一條最小的 traces pipeline

```yaml
receivers:
  otlp:
    protocols:
      grpc: {}
processors:
  memory_limiter: {}
  batch: {}
exporters:
  otlphttp/traces:
    endpoint: https://traces.example.internal
service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [memory_limiter, batch]
      exporters: [otlphttp/traces]
```

## 處理順序有意義

先限制記憶體可避免高流量時拖垮 Collector，批次處理則降低後端連線成本。若要移除敏感 attribute，應在 exporter 前加入明確的 transform 或 filter 規則，並以樣本資料驗證。
