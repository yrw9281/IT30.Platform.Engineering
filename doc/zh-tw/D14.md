# Day 14 - 統一聯動儀表板：整合 Prometheus、Loki 與 Grafana

## 前言

可觀測性的價值不在工具數量，而是調查時能否快速在 signal 之間跳轉。Prometheus 儲存 metrics，Loki 索引 logs，tracing backend 保存 spans，Grafana 則組合查詢與連結。

## 儀表板先回答營運問題

```promql
sum(rate(http_server_request_duration_seconds_count{service_name="catalog-api",status_code=~"5.."}[5m]))
/
sum(rate(http_server_request_duration_seconds_count{service_name="catalog-api"}[5m]))
```

## 建立可跳轉的共同欄位

```yaml
labels:
  service_name: catalog-api
  namespace: commerce
  trace_id: ${trace_id}
```

應以同一套 `service.name`、環境與 trace ID 命名跨系統關聯。Dashboard 應先呈現 SLI、版本與最近發布時間，再提供深入 Trace 與 Logs 的連結。
