# Day 27 - 政策即程式碼 (Policy as Code)：OPA Gatekeeper 架構解析

## 前言

RBAC 允許某人建立 Deployment，卻不會檢查該 Deployment 是否安全。Open Policy Agent（OPA）Gatekeeper 以 Admission Controller 在 API request 寫入前執行可版本化的規則。

## 規則與套用範圍分開

```yaml
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sRequiredLabels
metadata:
  name: require-owner-label
spec:
  match:
    kinds:
      - apiGroups: ["apps"]
        kinds: ["Deployment"]
  parameters:
    labels: ["app.kubernetes.io/owner"]
```

`ConstraintTemplate` 定義 Rego 與參數 schema；`Constraint` 決定哪些資源套用及採用哪些參數。這個分離讓同一規則能在不同團隊 Namespace 採取不同限制。

## 漸進導入

先以 audit 模式盤點違規資源與例外，再切到 deny。政策 repository 也要經過 code review、測試與版本控制，否則它只會成為另一種難以追蹤的叢集設定。

## 結語

Gatekeeper 提供集中式治理入口。明天把最常見的資源限制、特權容器與 image registry 規則寫成具體 Rego。
