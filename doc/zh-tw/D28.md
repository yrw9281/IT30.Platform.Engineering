# Day 28 - OPA 實戰：撰寫 Rego 規則動態阻擋高風險 YAML

## 前言

好的 Policy as Code 要回傳可行的錯誤訊息，並且只阻擋有明確安全價值的風險。今天聚焦三類規則：resource limits、privileged container 與受信任 registry。

## 強制 CPU 與 Memory limits

```rego
package k8srequiredlimits

violation[{"msg": msg}] {
  container := input.review.object.spec.template.spec.containers[_]
  not container.resources.limits.cpu
  msg := sprintf("container %q must set resources.limits.cpu", [container.name])
}
```

## 阻擋 privileged container

```rego
violation[{"msg": msg}] {
  container := input.review.object.spec.template.spec.containers[_]
  container.securityContext.privileged == true
  msg := sprintf("container %q must not run privileged", [container.name])
}
```

Image registry 規則應解析完整 image reference，接受明確的內部 registry 前綴而非用鬆散字串包含判斷。每個 Constraint 都需有測試案例，涵蓋允許、拒絕與缺漏欄位。

## 結語

Admission policy 把安全預設推到所有服務之前。最後兩篇將處理服務間流量，讓零信任不只停留在資源建立階段。
