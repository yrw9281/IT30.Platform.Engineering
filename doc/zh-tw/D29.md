# Day 29 - 零信任網格 (一)：Istio 架構與無侵入式流量管控

## 前言

Service Mesh 將連線安全、流量策略與 telemetry 從 application code 抽離。Istio 透過 Envoy sidecar 攔截 Pod 進出流量，由 control plane 發布設定與身分資料。

## 以 Namespace 開啟 sidecar injection

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: commerce-dev
  labels:
    istio-injection: enabled
```

## 流量策略的宣告位置

```yaml
apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: catalog-api
spec:
  host: catalog-api.commerce-dev.svc.cluster.local
  trafficPolicy:
    loadBalancer:
      simple: LEAST_REQUEST
```

Sidecar 並不會自動修復所有應用問題：資源消耗、startup 行為、debug 路徑與 egress 需求都需納入導入計畫。先從少量 Namespace 與可觀察的服務開始。

## 結語

Istio 已接管服務流量。明天在此基礎上啟用 mTLS 與 `AuthorizationPolicy`，明確規定誰可以呼叫誰。
