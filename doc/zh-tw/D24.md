# Day 24 - 狀態反饋閉環 (一)：配置 ArgoCD Health Checks 與 Notifications

## 前言

Argo CD 預設不理解 `Microservice` 的語意。自訂 health check 可以讀取 CR `status.phase`，將底層 Deployment 的收斂結果映射成 `Healthy`、`Progressing` 或 `Degraded`。

## Health Lua 的規劃片段

```lua
hs = {}
if obj.status == nil or obj.status.phase == nil then
  hs.status = "Progressing"
  hs.message = "Waiting for operator status"
elseif obj.status.phase == "Healthy" then
  hs.status = "Healthy"
  hs.message = "All managed resources are ready"
else
  hs.status = "Degraded"
  hs.message = obj.status.message or "Microservice is not healthy"
end
return hs
```

## 事件通知的前提

notification 應以 application health transition 為觸發，不應為每次 reconcile 發送訊息。事件 payload 至少帶上 Application、環境、revision 與 health 狀態，供下一篇 IDP webhook 更新資料庫。
