# Day 25 - 狀態反饋閉環 (二)：透過 Webhook 將 K8s 狀態打回 IDP DB

## 前言

Portal 若只顯示「已送出」，開發者仍得切換到 Argo CD 查結果。Argo CD Notification webhook 可在 Application health 改變時通知 IDP API，由後端驗證來源並更新服務交付狀態。

## Webhook payload 的最小欄位

```json
{
  "application": "catalog-api-dev",
  "revision": "a1b2c3d",
  "syncStatus": "Synced",
  "healthStatus": "Healthy",
  "environment": "dev"
}
```

## API 接收端的安全要求

```yaml
webhook:
  authentication: HMAC signature
  replayProtection: event-id
  acceptedSources:
    - argocd-notifications
```

處理必須 idempotent：相同 event 重送不應重複寫入歷史或倒退狀態。資料庫記錄應關聯 application、revision、時間與失敗訊息，Portal 才能顯示「哪一次交付」的結果。

## 結語

IDP 至此具備從意圖到狀態的閉環。接下來為這條自助路徑加上多租戶權限邊界，避免便利變成越權。
