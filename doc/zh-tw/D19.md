# Day 19 - 定義團隊的基礎設施合約：設計專屬 App Spec (CRD)

## 前言

`Microservice` CRD 的重點不是重做 Kubernetes，而是只開放開發者真正需要選擇的欄位，並把平台預設藏在 Operator 的實作中。

## 開發者提交的服務意圖

```yaml
apiVersion: platform.example.io/v1alpha1
kind: Microservice
metadata:
  name: catalog-api
spec:
  image: registry.example.internal/catalog-api@sha256:******
  port: 8080
  replicas: 2
  env:
    LOG_LEVEL: info
```

## Schema 要防止什麼

```yaml
openAPIV3Schema:
  properties:
    spec:
      required: [image, port]
      properties:
        port:
          type: integer
          minimum: 1
          maximum: 65535
```

`status` 由 Operator 寫入 observed generation、資源名稱與 readiness，不讓使用者偽造成功狀態。密鑰值不應作為明文 `env` 欄位的一部分。
