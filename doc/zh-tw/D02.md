# Day 02 - K8s 核心心智模型：宣告式 API 與控制迴路 (Reconcile Loop)

## 前言

Kubernetes 不要求我們描述「每一步怎麼做」，而是提交資源的期望狀態。控制器持續比較期望與實際狀態，直到兩者收斂；GitOps 與 Operator 都建立在這個模型上。

## 期望狀態不是一次性命令

以下片段表達「希望一直有三個副本」，不是「現在建立三個 Pod」。某個 Pod 消失後，Deployment controller 會再次執行 reconcile，補回差額。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: catalog-api
spec:
  replicas: 3
  selector:
    matchLabels:
      app: catalog-api
```

## 控制器的共同模式

```text
watch resource event
read desired state
observe actual state
apply minimal change
update status
```

`spec` 是使用者或平台要求的目標，`status` 則是 controller 回報的觀察結果。後續自製 CRD 也應維持這個責任分界。
