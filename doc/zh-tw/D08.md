# Day 08 - 大規模多環境管理：ArgoCD ApplicationSet 動態生成

## 前言

當十個服務各有三個環境，維護三十份相似的 `Application` 並不是好擴展方式。`ApplicationSet` 以 generator 取得服務或環境清單，再套入共用 template。

## 用 Git 目錄生成應用

```yaml
apiVersion: argoproj.io/v1alpha1
kind: ApplicationSet
metadata:
  name: platform-apps
spec:
  generators:
    - git:
        repoURL: https://github.com/example/platform-config.git
        revision: main
        directories:
          - path: apps/*/overlays/dev
  template:
    metadata:
      name: "{{path[1]}}-dev"
    spec:
      source:
        repoURL: https://github.com/example/platform-config.git
        path: "{{path}}"
      destination:
        server: https://kubernetes.default.svc
        namespace: "{{path[1]}}-dev"
```

## 模板化的界線

generator 適合生成結構一致的部署；例外需求不該塞進難讀的 template 條件式。保留可理解的目錄約定，才讓服務新增流程真正可預測。

## 結語

ApplicationSet 解決的是部署物件的規模。下一篇聚焦單一服務的發布風險，導入 Canary 的漸進式控制。
