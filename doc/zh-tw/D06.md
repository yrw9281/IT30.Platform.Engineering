# Day 06 - GitOps 哲學解析：以 Git 作為單一真實來源 (Single Source of Truth)

## 前言

傳統 CI 常直接用叢集憑證推送部署；GitOps 則由叢集內的 controller 從 Git 拉取期望狀態。差異不只是工具，而是權限與稽核責任的重新分配。

## 兩種部署方向

```text
Push: CI -> cluster API
Pull: Git <- CI, Argo CD -> Git -> cluster API
```

GitOps repository 應保存可重建環境的宣告，而非只留部署指令。每次 Image reference 或設定變更都經由 commit、review 與歷史紀錄。

```yaml
image:
  repository: registry.example.internal/catalog-api
  digest: sha256:****** 
```

## 為何是單一真實來源

當 Git 與叢集狀態不一致時，controller 會偵測 drift 並依設定修正；災難復原也變成重新同步已 review 的宣告。密鑰不應提交 Git，應交由 Secret 管理方案在部署時注入。

## 結語

GitOps 將部署意圖變成可審查的資料。下一篇導入 Argo CD，讓這個 pull-based 控制迴路真正運行。
