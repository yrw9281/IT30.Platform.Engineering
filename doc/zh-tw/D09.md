# Day 09 - 現代化進階發布：結合 Argo Rollouts 實現 Canary 金絲雀部署

## 前言

RollingUpdate 只管副本替換，無法原生表達「先給 10% 流量、觀察指標再擴大」。Argo Rollouts 用 `Rollout` 將發布步驟與分析條件寫成宣告。

## 將發布策略放進資源

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Rollout
metadata:
  name: catalog-api
spec:
  strategy:
    canary:
      steps:
        - setWeight: 10
        - pause:
            duration: 5m
        - setWeight: 50
        - pause: {}
```

## 指標是 promotion 的依據

下一步的規劃會把 AnalysisTemplate 連到 Prometheus，讓錯誤率或延遲超過門檻時中止發布。範例門檻必須依服務 SLO 調整，不能把固定數字當通用安全線。

## 結語

Canary 將發布風險拆成可觀察的小步。接著要建立共同語言，讓 Metrics、Logs 與 Traces 能回答這些發布是否健康。
