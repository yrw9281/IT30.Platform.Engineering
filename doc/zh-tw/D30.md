# Day 30 - 零信任網格 (二)：mTLS 雙向加密與 AuthorizationPolicy 實戰

## 前言

零信任的重點不是「內網也加密」而已，而是每次服務呼叫都要具備可驗證身分並符合明確授權。Istio mTLS 處理工作負載間加密，`AuthorizationPolicy` 則限制可接受的呼叫來源。

## 強制 Namespace 內使用 mTLS

```yaml
apiVersion: security.istio.io/v1
kind: PeerAuthentication
metadata:
  name: default
  namespace: commerce-dev
spec:
  mtls:
    mode: STRICT
```

## 只允許指定服務呼叫

```yaml
apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: catalog-api-ingress
  namespace: commerce-dev
spec:
  selector:
    matchLabels:
      app: catalog-api
  rules:
    - from:
        - source:
            principals:
              - cluster.local/ns/commerce-dev/sa/web-api
```

先套用 `STRICT` 前要確認所有 client 都已進入 mesh，否則會造成預期外的連線中斷。授權策略應先建立必要 allow list，再逐步縮小範圍；空的 allow policy 代表拒絕所有流量。
