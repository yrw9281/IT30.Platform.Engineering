# Day 23 - IDP 後端開發 (二)：自動化 Pull Request 與配置防呆校驗

## 前言

GitOps 的便利不應跳過 review。IDP 可為每次請求建立短期 branch、執行 schema validation，再建立 Pull Request 交給團隊或平台審查。

## PR 內容的規劃

```yaml
branch: idp/catalog-api-dev-20260915
changes:
  - apps/catalog-api/dev/microservice.yaml
checks:
  - kubectl-apply-dry-run
  - crd-schema-validation
  - policy-validation
```

## 驗證不是一個布林值

```json
{
  "valid": false,
  "errors": [
    {"field": "spec.image", "message": "image must use the approved registry"}
  ]
}
```

後端要將欄位錯誤回傳 Portal，避免把不明確的 Git API 失敗訊息丟給開發者。schema validation 檢查結構，Policy 則檢查組織規則；兩者都需要保留在 merge 前的 CI。
