# Day 07 - ArgoCD 實戰入門：宣告式持續交付引擎架構與部署

## 前言

Argo CD 監看 Git repository，將 `Application` 指向的路徑渲染後比對目標叢集。它將同步結果與健康狀態顯示成可追蹤的部署事實。

## Application 是部署宣告

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: catalog-api-dev
spec:
  source:
    repoURL: https://github.com/example/platform-config.git
    path: apps/catalog-api/overlays/dev
    targetRevision: main
  destination:
    server: https://kubernetes.default.svc
    namespace: catalog-dev
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
```

## 同步前要問的問題

`prune` 會刪除 Git 已不存在的受管資源，`selfHeal` 會修正手動 drift。兩者能提高一致性，也要求 repository 的權限與 review 規則足夠嚴謹。

## 結語

一個 `Application` 管理一個明確的部署單位。服務與環境變多後，手寫它們會再次成為摩擦，下一篇交給 `ApplicationSet` 動態生成。
