## 前言

Monitoring 擅長回答已知問題是否觸發警報；Observability 則讓我們由系統輸出探索未知問題。要做到後者，三種 telemetry signal 必須能從同一個服務與請求互相定位。

## 三種訊號各自回答什麼

```text
Metrics: 現在的錯誤率、延遲、飽和度是否異常？
Logs: 某次失敗當下記錄了哪些上下文？
Traces: 這個請求跨過哪些服務，時間花在哪裡？
```

```json
{
  "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
  "service.name": "catalog-api",
  "http.response.status_code": 500
}
```

## 設計原則

日誌應帶入 `trace_id`；Metric label 不可放高基數值如 request ID；Trace attributes 避免攜帶個資與密鑰。先定義共同資源屬性，才不會每個服務各自命名。
