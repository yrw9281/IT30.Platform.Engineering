# Day 18 - 平台工程架構藍圖：鋪設黃金路徑與 IDP 控制流設計

## 前言

平台不是另一套部署工具，而是將團隊安全且可觀察的做法產品化。開發者提交服務意圖，Portal、GitOps、Operator 和觀測系統各自負責一段明確的控制流。

## 控制流與回饋流

```text
Portal -> API -> Microservice YAML -> Git -> Argo CD -> Kubernetes
                                                    -> Operator -> resources
Argo CD health -> notification webhook -> IDP API -> Portal status
```

## 黃金路徑的輸入

```yaml
service:
  name: catalog-api
  image: registry.example.internal/catalog-api@sha256:******
  port: 8080
  owner: commerce
```

平台必須把「允許什麼」寫成合約與 policy，而不是依賴口頭規範。Portal 也不應直接持有叢集管理權限，所有部署意圖都需留下 Git 軌跡。

## 結語

架構先劃清責任。明天會把服務輸入具體化為 `Microservice` CRD，建立平台與開發者的最小合約。
