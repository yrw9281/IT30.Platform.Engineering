# Day 22 - IDP 後端開發 (一)：API 自動生成 YAML 並提交 GitOps 儲存庫

## 前言

Portal 後端不能直接建立叢集資源；它應驗證使用者輸入、產生 `Microservice` YAML，並經由 Git API 寫入 configuration repository。Git commit 是可稽核的部署請求。

## API 的輸入與產物

```json
{
  "name": "catalog-api",
  "image": "registry.example.internal/catalog-api@sha256:******",
  "port": 8080,
  "environment": "dev"
}
```

```yaml
# apps/catalog-api/dev/microservice.yaml
apiVersion: platform.example.io/v1alpha1
kind: Microservice
metadata:
  name: catalog-api
  namespace: commerce-dev
spec:
  image: registry.example.internal/catalog-api@sha256:******
  port: 8080
```

## 後端的責任

後端需驗證名稱、環境、Image registry 與使用者的 team 歸屬，並從 server-side mapping 決定 repository 路徑與 Namespace。不能讓 request 任意指定 Git path、branch 或 namespace。

## 結語

API 已能形成可 review 的 YAML 請求。下一篇將 direct commit 改為 Pull Request，並在 merge 前加入靜態合約檢查。
