# Day 04 - 彈性配置管理：Helm 與 Kustomize 實戰與選型

## 前言

Dev、Staging 與 Prod 的資源、Replica 與主機名稱不同，但不應複製三份幾乎相同的 YAML。Helm 適合以 values 參數化可重用的 Chart；Kustomize 適合以 base 與 overlay 宣告環境差異。

## Helm：以 values 填入模板

```yaml
# values-prod.yaml
replicaCount: 3
image:
  repository: registry.example.internal/catalog-api
  tag: "1.2.0"
resources:
  requests:
    cpu: 250m
    memory: 256Mi
```

## Kustomize：以 overlay 疊加差異

```yaml
# overlays/prod/kustomization.yaml
resources:
  - ../../base
namespace: catalog-prod
patches:
  - path: deployment-replicas.yaml
images:
  - name: catalog-api
    newTag: "1.2.0"
```

## 選型原則

若要發布第三方軟體或提供帶參數的共用套件，優先考慮 Helm；若團隊想保留原生 YAML 並讓環境差異清楚可 review，Kustomize 通常更直觀。兩者也可搭配：Helm 產生基底，Kustomize 負責環境覆寫。

## 結語

參數化解決環境差異，但 Kubernetes 仍只認得內建資源。下一篇會擴充 API，讓叢集理解團隊自己的服務合約。
