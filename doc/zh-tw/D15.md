# Day 15 - GitHub Actions 基礎：現代化 CI 工作流與 Pipeline 設計

## 前言

CI 的責任是驗證原始碼並產出可追溯 artifact，不直接決定叢集狀態。工作流應在 Pull Request 早期回饋品質問題，並在可控的權限範圍內執行。

## 以 PR 為觸發點

```yaml
name: ci
on:
  pull_request:
permissions:
  contents: read
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm test
```

## Pipeline 設計原則

先執行速度快且能早失敗的 lint、unit test，再進行 build 與 image scan。Action 一律固定 major 或 commit SHA；token 權限採最小權限，避免把部署憑證放進一般測試工作。
